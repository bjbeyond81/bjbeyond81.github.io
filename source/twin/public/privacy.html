Privacy, in plain language

Twin 2.0 · 29 October 2026

Journal and local access

Your profile, entries, mood, sleep, expenses, embeddings, questions, answers and letters are stored in an AES-256-GCM encrypted IndexedDB vault. Saved voice recordings are encrypted separately. A random, non-exportable encryption key and the verified activation code remain in the same browser so Twin can reopen automatically without a journal password. Anyone using that unlocked browser can open your journal. Protect your device with its screen lock.

AI and voice stay on-device

Text generation, semantic memory and optional Whisper transcription run in browser workers. Recording starts only after your action and microphone permission. Audio is not sent to a remote recognition service. A stopped recording is a temporary draft until you save the memory. Recording stops when the app is hidden. There are no advertising profiles, application analytics or remote inference APIs.

Downloads and browser storage

Hosting and public model providers receive ordinary download requests, including IP address and browser metadata, under their policies. These requests do not contain diary text, questions or audio. Twin uses IndexedDB for encrypted data, local key and activation; OPFS, Cache Storage and engine IndexedDB for public models/offline files; and localStorage for language, appearance and AI preferences. It sets no application cookies. The optional voice model downloads on first transcription.

Backups and migration

New encrypted JSON backups include saved recordings and use the activation code as their secret, with PBKDF2-SHA256 at 600,000 iterations and AES-256-GCM. Keep the code and backup separately: anyone holding both can restore the contents. Models and unsaved drafts are excluded. Restore replaces local data. A version 1 journal or backup requires its original password to decrypt; local migration asks for it once and retains the original encrypted envelope as a recovery copy until full erasure.

Retention and deletion

Data stays until you delete it or the browser removes storage. Export regular backups; persistence requests do not guarantee retention. There is no cloud sync or journal recovery service. Settings can export, restore and erase all local data, including the local key, activation, recovery copy and audio. Model-cache deletion is attempted; other tabs can block cleanup. Exported files must be removed separately. Deleting one note does not remove text already copied into saved chat citations.

Limits of protection

This design provides convenient local access, not a separate authentication lock. There is no inactivity password prompt. After five background minutes, AI workers stop to release memory while the journal remains open. Compromised devices, extensions, keyboards or app code can access decrypted content. Use a personal browser profile; avoid entering other people's sensitive information without appropriate permission.

Purchases and support

Shopify purchases, payment records and support are separate from your local journal. Use the seller contact supplied with your order; do not send diary contents, recordings, activation codes or backups to support. The seller must provide its own identity, contact and privacy information for commercial processing. This page describes the software and does not certify the seller's legal compliance.
